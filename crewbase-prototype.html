Crewbase 交互设计文档

Local-First、模型无关、可自托管的多 Agent 协作工作台。本文档把 PRD 的能力清单转成界面结构、关键流程和组件规范，供设计、前端和 Go 守护进程团队对齐。

MITmacOS · Windows · Linux桌面端优先，移动端为通知与审批伴侣

1产品分析

PRD 的核心判断是：「Always-on AI 同事」这一品类已经被验证，但现有产品要么贵且锁模型，要么开源却不能商用或不安全。Crewbase 的机会在于同时满足四点：复用已有订阅、模型可替换、默认安全、可商用。

痛点与界面应答

PRD 痛点用户实际感受界面上的应答
订阅贵、按量叠加「我已经付了 Claude 和 ChatGPT，还要再付一份」「模型与订阅」页把订阅额度做成一等公民；分流规则显示本地模型节省了多少 token
模型锁定「Claude 限流了，整个任务就停了」Agent 与模型解耦；频道内用一条分隔标记说明切换，工作不中断
开源方案默认全权限「不敢让它在我电脑上跑」运行模式默认 B 容器沙箱；开启 C 需二次确认并限时；高危动作走审批卡片
协作能力弱「多个 Agent 各干各的，不知道谁在负责」频道顶部常驻「当前任务 + 主责人」条；交接以卡片形式出现，可停止、改派、归档

2设计原则

Agent 是实体，模型是零件

界面以人格化的 Agent（名字、头像、职责）为中心。模型只出现在消息元信息和路由设置里，切换模型不改变 Agent 身份。

任何时刻都知道谁在负责

频道顶部固定显示当前任务、主责人和状态。一次只有一个主责人，交接必须显式发生。

风险用颜色和位置说话

琥珀色只表示「在等人」，红色只表示「失败或越权」。等待审批的项目同时出现在频道、审批中心和侧栏徽标。

默认安静

巡检无异常不发消息；晨报只列需要处理的事，正常项折叠。通知是稀缺资源。

本地优先要看得见

主机切换器常驻侧栏顶部，写明数据在哪里；记忆和指令是可打开的本地文件，不藏在黑盒里。

人可以随时接管

停止、改派、接管浏览器都在一次点击之内，且不会丢失 Agent 的工作区与队列。

3信息架构

窗口分为三列：会话列表找人和事，对话区工作，右侧面板看细节。我们不用 openbot / cindy 那种最左侧的竖向图标栏：自动化、审批、模型、插件、权限、主机统一收进「设置」（标题栏齿轮）；模型选择器放在输入框里；「需要你」和快速跳转放在标题栏右侧。

4核心交互流程

以下四条流程覆盖 PRD 中最有差异化的能力，原型中均可操作。

4.1 任务交接One Task Owner
  1. 人在频道中 @ 某个 Agent 指派任务，该 Agent 成为主责人，任务条更新运行中
  2. 主责人完成阶段工作，发出交接卡：目标 Agent、交接说明、产物文件交接中
  3. 接收方确认后成为新主责人；原主责人回到空闲。文件引用随卡片移交，不复制运行中
  4. 人可以随时停止、改派或归档。改派时弹出 Agent 选择器，显示各自队列长度已暂停
4.2 审批挂起与恢复Human-in-the-Loop
  1. Agent 调用命中 Ask 规则（如 git push、对外发帖），守护进程挂起执行流并保存断点等待审批
  2. 同时出现在三处：频道内审批卡、审批中心、侧栏徽标；并推送到移动端或 IM等待审批
  3. 审批卡展示：谁、要做什么（完整命令或内容预览）、命中的规则、影响范围等待审批
  4. 批准 → 从断点继续；拒绝 → Agent 收到拒绝原因并重新规划；超时 → 按工作流配置取消已恢复
4.3 限额无损切换Zero-Loss Fallback
  1. 主模型返回 rate limit 或额度耗尽，调度器按 Agent 的路由顺序选择下一个可用模型切换中
  2. 工作区、压缩后的上下文和待办队列交给新模型，Agent 身份不变切换中
  3. 频道插入一条分隔标记：「Kai 的 Claude Code 已达上限 · 改用 Codex」，不发通知运行中
  4. 主模型额度重置后，下一个新任务自动回到首选模型；进行中的任务不打断运行中
4.4 浏览器接管Takeover
  1. Agent 遇到登录、2FA 或验证码，标记为「等待接管」并暂停等待接管
  2. 人点击「接管浏览器」，画面加蓝色描边表示人在控制；Agent 不读取画面与输入人工控制
  3. 完成后点击「交还控制权」，Agent 从已登录状态继续，凭证不进入提示词与日志已恢复

5页面规格

页面目标关键组件边界情况
频道看懂谁在做什么，必要时介入任务条（主责人、状态、停止/改派/归档）、消息、交接卡、审批卡、模型切换标记、@ 输入框无任务时任务条显示「空闲，@ 一个 Agent 开始」；多人同时 @ 时进入队列并提示排位
Agent 详情配置一个长期同事模型路由（可拖拽排序）、推理强度、运行模式 A/B/C、上下文用量（80% 阈值线）、FIFO 队列（暂停、插队、取消）、工作区链接切到 C 需二次确认并默认限时 24h；路由中所有模型都不可用时 Agent 状态变红并通知
右侧面板不离开对话就能看任务、文件和 Agent 设置三个标签：任务（负责人、状态、成员、队列）、文件（工作区文件树与预览）、Agent 设置（模型顺序、推理强度、运行权限、上下文、记忆）窄屏下变为浮层；点消息里的文件 chip 自动打开「文件」并定位
标题栏与输入框随手调整当前 Agent右上角模型选择器「模型 · 推理强度」；输入框内权限下拉；输入框下方显示主机与目录、订阅剩余额度、上下文占用已达上限的模型在菜单中置灰并显示重置时间；选「宿主机授权」先在输入框上方展开确认条
插件与技能扩展 Agent 能力插件 / 技能分段、搜索、导入、目标主机选择、分类筛选、安装状态卡片切换主机后只管理该主机，提示「更改只保存在这台电脑上」
审批中心集中处理所有等人的事审批项（来源 Agent、动作、完整内容、命中规则、等待时长）、批准 / 拒绝 / 查看详情、历史同一 Agent 连续多条相似请求可「本次会话内都允许」；拒绝时可填原因回传给 Agent
浏览器接管完成 Agent 无法完成的人类验证实时画面、URL、接管 / 交还按钮、隐私说明、任务上下文接管超过 15 分钟未操作则提醒；网络断开时保持 Agent 暂停
工作流把重复流程固化下来横向画布（触发器 → 串并行步骤 → 审批卡点）、步骤设置面板、运行记录窄屏下画布横向滚动；某步失败时运行记录标红并可从该步重跑
例行巡检后台盯着，只在需要时出声巡检列表（Agent、频率、汇报条件、模式、开关）、晨报预览巡检默认只读模式；需要写入的巡检显示「沙箱」标签
权限规则定义自动化的边界动作类别 × Allow / Ask / Block 分段控件，修改即保存「外部支付」不允许设为 Allow；单个 Agent 只能收紧不能放宽全局规则
模型与订阅看清额度和花费订阅轨（额度条、重置时间）、API 与本地轨、分流规则表CLI 未登录时给出终端命令；本地服务未启动时显示灰色但保留配置

6状态模型

Agent 状态同时出现在侧栏头像角标、频道任务条和 Agent 详情页顶部，三处使用同一套颜色。

空闲 运行中 切换模型中 等待审批 等待接管 已暂停 已完成 失败 / 无可用模型

规则：琥珀色 = 需要人；红色 = 出错；蓝色 = 正在工作；绿色只用于结果，不用于常驻状态。

关键组件

  • 审批卡：琥珀色淡底 + 琥珀描边；必须展示完整命令或内容预览；主按钮「批准」，次按钮「拒绝」；处理后变为普通卡片并写明处理人和时间。
  • 交接卡：中性卡片，「A → B」+ 交接说明 + 文件 chip，不使用强调色。
  • 模型切换标记：横贯消息流的细分隔线 + 居中说明，不发通知、不打断阅读。
  • 运行权限：输入框内下拉快速切换，右侧面板中用三张卡片说明差异；选中 B 为蓝色描边，选中 C 为红色描边并先展开确认条。
  • 模型选择器：固定在标题栏右上角，显示「厂商色块 + 模型名 · 推理强度」，菜单内列出该 Agent 的模型顺序与剩余额度。
  • Agent 头像：圆角方块 + 两只眼睛，颜色即识别色；右下角圆点表示状态。
  • 尺寸：控件高度 24 / 28 / 32 / 36；圆角 6（控件）、8（按钮）、12（卡片）、14（窗口）。

9待决问题

交接是否需要接收方「确认」？自动接收更流畅，但人难以在中途拦截。建议：默认自动，频道可设为「交接需人确认」。
模型切换后是否回切？回切可能导致上下文风格不一致。建议只在新任务开始时回到首选模型。
移动端的审批深度代码 diff 在手机上难以审阅。建议移动端对「代码推送」只提供「稍后在桌面处理」与「拒绝」。
产品命名PRD 未给出产品名，本文档使用暂定名 Crewbase，需避免与 OpenBot 品牌混淆。
远程主机上的浏览器接管帧流延迟与带宽需要技术验证，决定接管画面是实时流还是逐帧截图。
