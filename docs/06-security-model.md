# 安全模型

## 0. 先说清楚能保证什么

沙箱、审批和权限规则可以**降低**风险，但**不能保证**隔离，也不能保护 Crewbase 已经获准访问的资源。这是 DeepSeek Harness 在其 `SAFETY` 文档中的表述，我们完全认同，并要求产品文案、文档、营销页都遵守：

- 不使用「绝对安全」「完全隔离」之类的说法。
- 首次启动时说明：Agent 会执行模型生成的命令，可能修改或删除文件、泄露数据。
- 建议用户只授予最小权限，备份 Agent 能访问的文件，在专用环境或容器中运行高风险任务。

## 1. 威胁模型

| 威胁 | 来源 | 主要防线 |
|---|---|---|
| 模型执行了破坏性命令 | 模型错误、提示词注入 | 运行模式、规则引擎、审批 |
| 网页或文件里的提示词注入让 Agent 对外发消息或泄露数据 | 不可信内容 | 只读调研模式、对外发布默认 Ask、网络白名单 |
| 第三方插件越权 | 恶意或有缺陷的插件 | 进程外 / WASM 运行、权限清单、用户批准 |
| 凭证泄露到模型或日志 | 工具输出、错误信息 | 凭证引用、结果脱敏、诊断信息上限 |
| 远程主机被扫描或入侵 | 公网暴露 | 零入站端口、出站加密配对、远程调用白名单 |
| 自动化失控（循环续跑、重复投递） | 工作流、目标续跑、定时任务 | 轮次上限、恢复后需重新授权、幂等投递 |

## 2. 三档运行模式

运行模式是一个**权限预设**，由两个独立的旋钮组合而成。界面上只显示预设名，底层仍是两个旋钮（借鉴 Harness 的 `permission-presets`）。

| 预设 | 文件沙箱 | 网络 | 审批策略 | 对应 Harness 沙箱模式 |
|---|---|---|---|---|
| A · 只读调研 | 只读 | 仅白名单域名，或只允许 `web` 能力 | Ask | `read-only` |
| B · 容器沙箱（默认） | 只能写项目挂载目录（包管理器缓存在独立临时目录） | 开放（配置了 allowHosts 时为白名单） | 工作区内删除不再询问；推送 / 对外发布 / 花钱仍 Ask | `workspace-write` |
| C · 宿主机授权 | 不限制 | 不限制 | Ask（不允许设为 never） | `danger-full-access` |

要点：

1. **Harness 的文件沙箱只管文件效果，不管网络和进程可见性**。我们的容器模式要管网络，因此网络是**第三个独立旋钮**，由 `sandbox-docker` 等提供方实现（Docker 网络策略或出站代理白名单）。
2. **沙箱策略随每次调用携带**，不固定在提供方上。优先级：本次已批准的显式模式 > 会话当前模式 > 部署默认值。
3. **一次性提权就是一次新调用**：Agent 请求更宽的权限时走审批，批准后只对这一次调用生效。
4. **执行程度必须如实上报**。提供方返回 `enforcement: full | partial`。无法完全执行的情况（例如网络白名单只能放开网络）报告 `partial`，界面在权限下拉旁显示「部分隔离」提示。
5. **后端不可用时关闭式失败**。沙箱后端不可用（例如 Docker 未启动）时报 `SANDBOX_UNAVAILABLE`，绝不静默降级为不隔离直接执行。
6. **区分「被沙箱拦截」与「沙箱自身故障」**。提供方给出拦截特征（如 stderr 模式），让 Agent 知道该请求提权，而不是反复重试。
7. **C 模式由人开启**：开启时展开确认条，开启后一直有效，直到人切回 B。规则引擎的 Ask / Block 在 C 模式下继续生效。（早期版本的授权 24 小时后自动恢复 B；升级时仍在有效期内的授权改为长期有效，已过期的保持 B。）
8. **运行时授予的可写目录在恢复或 fork 后失效**，需要重新授权。
9. **受保护路径（`ProtectedRoots`）在可写目录里也保持只读**，用于编码 CLI 的项目配置（`.claude`、`.mcp.json` 等）。seatbelt 用最后生效的 deny 规则；bubblewrap / Docker 把已存在的路径只读绑定到自身，不存在的名字挂一个只读空 tmpfs，使其无法被创建——挂载点会在命令运行期间以空目录出现在文件夹里，命令结束后删除。`sandbox-none` 不执行任何隔离，沙箱模式下直接拒绝运行命令，只剩文件工具的拒绝和 Agent 自己工作区的隔离移走兜底。

### 沙箱后端

| 平台 | 提供方 | 技术 |
|---|---|---|
| macOS（默认） | `sandbox-seatbelt` | `sandbox-exec` 配置文件，按每次调用的策略生成 |
| Linux（默认） | `sandbox-namespace` | bubblewrap：整个文件系统只读挂载、可写目录单独绑定，新的 PID / IPC / UTS / 网络命名空间，丢弃 capabilities；需要非特权 user namespace 或 setuid 的 bwrap |
| 其他平台（默认）/ 任意平台可选 | `sandbox-docker` | 容器里执行：`--security-opt no-new-privileges:true`、`--shm-size 1g`、工作区绑定挂载、`--network none`；可选自定义 seccomp profile（`seccompProfile`）和 `--user` |
| 任意平台 | `sandbox-none` | 不做隔离：沙箱模式下直接拒绝运行命令，只用于没有可用后端的环境 |

默认按平台选择（`bundles/bundles.go` 的 `defaultSandbox`），可以用补丁换成其他提供方：

```yaml
- id: sandbox
  name: '@crewbase/sandbox-docker'
```

网络白名单目前没有按域名过滤的出站代理：三个隔离后端遇到 `allowlist` 都只能放开网络，并如实上报 `enforcement: partial`。远程主机上的执行由那台主机上的 `crewd` 和它自己的沙箱负责（见第 8 节「远程主机与多端」），没有单独的 SSH 沙箱后端。

## 3. 规则引擎：Allow / Ask / Block

- 规则引擎是 `tools/pre-execute` Waterfall 的一个监听器（见 [插件系统 · 工具执行流水线](05-plugin-system.md#5-工具执行流水线)）。Block 时短路，Ask 时把决策标记为需审批后交给下游。
- 按动作类别匹配：

默认值如下。产品不提供规则表格设置页，用户在审批时调整（见下文「记住的选择」）。

| 类别 | 默认 | 可否改为不再询问 |
|---|---|---|
| 读取文件与网页 | Allow | 是 |
| 执行命令（沙箱内） | Allow | 是 |
| 安装依赖 | Allow | 是 |
| 代码推送、合并 PR | Ask | 是 |
| 文件删除 | Ask | 是 |
| 对外发消息 / 发布（邮件、社媒、IM） | Ask | 是，但需二次确认 |
| 付费生成（`spend`：按次 / 按秒计费、但不是支付，例如生成视频） | Ask | 是 |
| 外部支付 | Block | **否** |

**图片 / 视频生成**（features/media，见 [技术架构 §6.5.1](04-architecture.md)）：`image_generate` / `image_edit` 是「写文件」（Allow：一张图花费很小，结果只写进工作区；只读模式下被拦截），`video_generate` 是「付费生成」（Ask：一段视频按秒计费、可能几美元），审批卡写明「生成视频：一只猫…（8 秒，720p）」，可以「以后都允许」。`image_edit` 与 `video_generate` 的输入图片是工作区路径，经路径守卫限制在工作区内，读取时再次解析符号链接，只接受 PNG / JPEG / WebP 字节。生成结果按字节判断类型，HTML / SVG 等永远不会作为图片或视频保存或内联显示。提示词会发给所选提供方；只用本地模型的 Agent 不会被自动送到云端图片 / 视频模型。

- **作用域**：全局规则对所有 Agent 生效；单个 Agent 只能**收紧**（Allow → Ask / Block），不能放宽。实现上用 `tools.Restrict`（限制取交集）和 Agent 作用域的规则监听器。
- **硬约束放在守卫里**：路径越界、只读模式下的写操作等由守卫处理。守卫只能拒绝或弃权，不能被规则引擎或 Hook 重新放行。
- **记住的选择**：审批卡上的「以后都允许」= 批准本次 + 为该 Agent 写入一条 Agent 作用域的 Allow 规则（只能把 Ask 放宽为 Allow，不能动 Block）。所有记住的选择列在设置 › 审批，随时撤销；撤销后恢复为 Ask。「对外发消息」记住时需二次确认，「外部支付」不提供该按钮。
- 企业版可以由管理员下发规则（例如禁止任何人记住「对外发布」），下发的规则优先于个人选择。
- 规则变化发出 `rules/changed` 通知（不带差量），界面重新读取。

## 4. 审批

| 机制 | 说明 |
|---|---|
| 挂起 | 审批必须在一个未结束的轮次内发起；工具调用停在流水线中，Agent 的其他工作不受影响 |
| 不卡住 Agent | 等待审批时，Agent 收到别的事（另一个对话、IM、例行、后台结果）就先「停靠」这次调用：调用结束并告诉模型在等批准，审批请求本身不动，桌面和 IM 上照样可以批；同一对话里人直接回消息仍视为拒绝。人做出决定后，原对话里开一小轮告知 Agent：批准的那一次调用（同一 Agent、会话、工具、完全相同的参数）在 1 小时内可以不再询问执行一次，用后即失效；拒绝则重新规划。停靠中的调用记在 `parked.json`，重启丢失请求时告诉 Agent 需要的话重新发起 |
| 结果 | 闭合集合：`allowed-once` / `rejected` / `cancelled` / `unavailable`，只有 `allowed-once` 放行 |
| 应答方 | 通过 `approval/request` Waterfall 注册：桌面卡片、移动推送、IM 网关；第一个给出结果的应答方认领 |
| 关闭式失败 | 无应答方、应答方出错或超时一律为 `unavailable` |
| 策略 | 每个会话有 `ask` / `never`，以最后一条 `approval/policy` 会话事件为准；`never` 在分发前由审批服务自己拒绝 |
| 审计 | `approval/asked`、`approval/decided` 写入会话日志；写入失败则审批失败 |
| 记住选择 | 「以后都允许」生成一条 Agent 作用域的 Allow 规则，在设置 › 审批中列出并可撤销 |

**移动端与 IM 的审批深度**：代码推送类审批在手机上只提供「拒绝」和「稍后在桌面处理」，因为 diff 在小屏上难以审阅（待产品确认，见 [路线图](07-roadmap.md#待决问题)）。

## 5. 凭证

借鉴 Harness 的 `credentials` 能力：

- **配置里只存引用，不存值**。引用写作 `vault:crewbase/<名称>`，指向 Crewbase 自己的保管库；也可以写 `env:VAR`（环境变量，只读）。早期配置里的 `keychain:crewbase/<名称>` 指向保管库里的同一条，系统钥匙串不再使用（以前存在钥匙串里的密钥需要重新填写一次）。
- **保管库**（`capabilities/credentials/vault.go`）：数据目录下的 `vault/` 文件夹（0700）里有 `master.key`（32 字节随机主密钥）和 `vault.json`（两者都是 0600）。每个值用 AES-256-GCM 加密，条目名作为附加数据，挪到别的名字下就解不开。主密钥只靠文件权限保护，和 `~/.ssh` 私钥一样：能以这个用户身份读这两个文件的程序就能读到密钥。`vault.json` 先写临时文件再改名，崩溃不会写坏；主密钥丢了而 `vault.json` 还在时拒绝启动，不会悄悄换一个空的保管库。
- **设置 › 保管库** 按用途列出所有密钥（模型、MCP 服务器、MCP 登录、即时通讯、自己添加的），只显示掩码；可以添加、替换、删除，存进去的值读不回来（`GET/POST/PUT/DELETE /api/vault`，只限桌面端）。
- **每次使用时解析**，凭证轮换无需重启。
- **描述接口只返回元信息**：是否已配置、来源、可选的掩码预览（如 `sk-…4f2a`）。任何方法都不返回明文；明文只能单向写入。
- **空值视为不存在**。
- **需要刷新的令牌**（OAuth）在同一把锁下「读取 → 决定 → 替换」，避免并发刷新。
- **凭证不进入模型上下文**：适配器、MCP、插件通过 `credentials` 服务在宿主侧解析后使用，结果经 `tools/post-execute` 脱敏。
- **诊断信息有上限**：子 Agent、插件返回的诊断文本不得包含凭证或原始协议载荷，最长 4 KB。

## 6. 浏览器接管

- 每个 Agent 有独立的浏览器 Profile；浏览器归属于一个确定的会话，同一时刻只有一个会话能控制附加的外部浏览器。
- 接管期间 Agent 暂停，浏览器画面和键盘输入不发送给模型，也不写入日志。
- 登录状态保存在浏览器 Profile 中，不从日志恢复。
- 附加模式下（连接用户已打开的浏览器），清理时只断开连接，不关闭浏览器。
- **接管时切到真实窗口**：只能由接管者本人、只能从运行 Crewbase 的这台电脑（本机令牌、回环地址）发起；配对设备和中继只能用逐帧画面（窗口开在主机上，远端看不到）。切换是在同一 Profile 上先正常关闭再重开，Agent 全程暂停；会话 Cookie 只在内存里带过去，不落盘、不写日志；交还控制权前先回到无头模式。附加模式不能切换。
- **iframe**：快照和操作也进入 iframe（含跨源、进程外 iframe），脚本跑在框架的隔离 world，页面看不到元素编号；密码 / 验证码 / 卡号字段在 iframe 里同样拒绝输入；运行模式白名单也拦截进程外 iframe 发出的请求（iframe 在拦截开启前保持暂停）。

## 7. 插件安全

| 档位 | 默认信任 | 约束 |
|---|---|---|
| 内置插件 | 完全信任 | 随主程序签名发布，代码审查 |
| 进程外插件 | 按清单授权 | 只能调用清单中声明且用户批准的服务；网络、文件、凭证按清单限制；可选放进容器运行；Waterfall 监听超时 2 秒视为不改动 |
| WASM 插件 | 内存隔离 | 默认无系统调用；只能访问宿主显式传入的数据 |
| MCP 服务器 | 按连接授权 | 以服务器名为命名空间；由 `shell` / `sandbox` 能力托管进程 |
| 技能 | 内容型 | 只是 Markdown 与脚本；脚本执行仍走工具流水线和沙箱 |

- **进程外插件默认在沙箱里运行**，网络和文件只放行它声明过、用户批准过的；不进沙箱是一项要用户单独批准的权限。安装界面如实列出权限，不使用「安全插件」之类的标签。
- **新版本需要重新批准权限**，除非用户勾选「信任此发布者的后续版本」（借鉴 Harness 的 `approveFutureVersions`）。
- 插件卸载时，它注册的所有工具、监听器、界面都会撤销；进程外插件的子进程树被终止。
- **MCP**：host 信任的 stdio 服务器在沙箱之外运行，只读模式下只放行它的读取类工具（沙箱再强也管不到它）。HTTP 服务器的 OAuth 令牌只存保管库；登录回调只接受正在等待的那次登录的 state，并且只用一次；登录链接只接受 https（本机回环除外）。

## 8. 远程主机与多端

- **零入站端口**：远程主机只主动建立出站加密连接（WebSocket Relay / Tailscale / WireGuard），与已配对的桌面端和移动端通信。
- **远程调用白名单**：只有标记为远程的服务方法可被调用；顺序为先鉴权、再校验参数、最后解析对象和激活 Agent。被拒绝的调用不会激活任何 Agent，也不会泄露对象是否存在。
- **设备分级**：桌面端可以完全控制；移动端默认只能查看、审批、发消息，不能修改规则和安装插件。配对用一次性配对码（5 分钟、只能用一次、限速）；每台设备有自己的令牌，只存哈希，可单独移除并立即断开。
- **中继端到端加密**（features/relay）：配对链接把主机公钥放在 URL 片段里交给设备；设备与主机做 ECDH（主机静态密钥 + 双方临时密钥）派生 AES-256-GCM 密钥，帧带递增计数器，篡改、重放、乱序即断开。中继只转发密文，看不到令牌和内容；主机在中继上的身份是其公钥的哈希，用签名挑战证明。
- **成员与角色**（features/members）：主人持有本机令牌；其他人是成员，用自己配对的设备连接。角色：管理员（完全控制）、成员（查看、对话、批准被授权的操作类别）、只读（只能查看，网关只放行读取）。角色每次请求实时解析，改了立即生效；移除成员会撤销他的全部设备并断开。成员发的消息、做的审批都带上名字写入对话和审计日志，客户端自己填的发送人会被覆盖。付款类操作永远不能远程批准；任何能看到审批的成员都可以拒绝。

## 9. 自动化的安全边界

- **工作流与定时任务**：管理与投递串行排队；单个任务最小间隔 60 秒；投递带幂等键，避免「写入收件箱后、写回执前」崩溃导致重复执行。
- **目标续跑**：有轮次上限；`blocked` 状态带原因码；进程恢复或 fork 后，自动续跑默认关闭，需要人重新授权（借鉴 Harness 的「目标激活不参与回放」）。
- **任务板的写入范围只是提示，不是锁**；真正的写限制由沙箱的可写目录实现。

## 10. 审计（Phase 3）

- 审计日志记录：规则判定、审批请求与结果、运行模式变化、插件安装 / 启用 / 停用、凭证引用变化、远程登录与设备配对（配对 / 改名 / 移除），以及被拒绝的令牌（每个来源地址每分钟最多记一条，防止刷爆审计链）。
- **只读模式也保护放在临时目录里的工作区**：沙箱默认允许写临时目录作为草稿区，只读模式会把工作区额外列为受保护路径（Seatbelt 规则最后匹配者生效）。
- 只追加；导出时附带哈希链，便于校验是否被篡改。
- 审计事件不进入模型上下文。
