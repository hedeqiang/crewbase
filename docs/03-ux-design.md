# 交互设计

可点击原型：根目录的 [`crewbase-prototype.html`](../crewbase-prototype.html)，用浏览器直接打开。原型页右上角可以切换到网页版设计文档，内容与本文一致。

## 1. 设计原则

| 原则 | 说明 |
|---|---|
| Agent 是实体，模型是零件 | 界面以有名字、头像、职责的 Agent 为中心。模型只出现在输入框的选择器、消息元信息和路由设置里。切换模型不改变 Agent 身份 |
| 任何时刻都知道谁在负责 | 频道的右侧面板固定显示当前任务、负责人和状态。一次只有一个负责人，交接必须显式发生 |
| 风险用颜色和位置表达 | 琥珀色只表示「在等人」，红色只表示「失败或越权」，蓝色表示「正在工作」。等待审批的事项同时出现在对话、会话列表的「需要你」分组和对话标题栏右侧的「需要你」胶囊（只在有待处理事项时出现） |
| 默认安静 | 巡检无异常不发消息；晨报只列需要处理的事；模型切换只在对话中插入一行说明，不发通知 |
| Local-First 要看得见 | 输入框下方的状态行始终写明当前主机和目录，点击即可切换；记忆和指令是可以直接打开的本地文件 |
| 人可以随时接管 | 停止、改派、接管浏览器都在一次点击之内，且不丢失 Agent 的工作区与队列 |
| 扩展点在界面上也是插件 | 对话里的卡片、右侧面板的标签页、设置页的卡片都由插件注册。插件卸载时它的界面一并消失（见 [插件系统 · 界面扩展](05-plugin-system.md#8-界面扩展)） |

## 2. 视觉风格

参考 openbot.run：浅灰画布、白色内容面、极细边框、单一蓝色强调、胶囊形按钮；跟随系统深浅色。

| 角色 | 浅色 | 深色 |
|---|---|---|
| 画布 | `#F5F5F6` | `#1A1A1A` |
| 内容面 | `#FFFFFF` | `#1C1C1C` |
| 主文字 | `#141414` | `#ECECEE` |
| 强调 / 运行中 | `#007CF7` | `#1F8FFF` |
| 等待人 | `#F08A00` | `#FF9412` |
| 失败 / 越权 | `#E8222D` | `#FD2F3B` |
| 完成 | `#148A61` | `#199E70` |

- 字体：Inter + 系统中文字体（苹方 / 微软雅黑）；代码用系统等宽字体；数字用等宽数字。
- 圆角：控件 8，卡片 12–14，窗口 14；按钮与分段控件为胶囊形。
- Agent 头像：原创「队员徽章」——形状 + 名字首字，颜色即识别色；右下角圆点表示状态。识别色不与状态色混用。

## 3. 窗口结构

窗口分三列：会话列表、对话区、右侧面板。**没有独立的标题栏，也没有浏览器式的会话标签页**：会话列表本身就是切换入口，标签页只会重复它，并让产品看起来像浏览器。

- **顶部 44px 是标题栏区域**，由各列自己的顶部组成：会话列表顶部只放列表开关（靠右）；对话区顶部是**对话标题栏**；右侧面板顶部是它的标签页。整条可拖动窗口，按钮等控件不可拖动。
- **对话标题栏**：Agent 头像（24）+ 名字（600 字重）+ 灰色职责；运行中显示蓝色「正在工作…」，等审批显示琥珀色「等你批准」。频道显示「# 频道名」和「负责人 Kai」徽章。右侧是「需要你」胶囊——**只在有待处理事项时出现**，没有时什么都不显示——然后是右侧面板开关。
- **切换对话**：会话列表、⌘K，以及 ⌘[ / ⌘] 在最近打开的对话之间后退 / 前进（Windows / Linux 用 Ctrl）。
- **桌面壳**：Crewbase 桌面版运行在隐藏系统标题栏的 MyGo 窗口中，标题栏高度 44。页面读取 `--mygo-titlebar-height`、`--mygo-titlebar-inset-left`（macOS 红绿灯）和 `--mygo-titlebar-inset-right`：会话列表顶部左侧让出红绿灯，列表收起时由对话标题栏让出。桌面壳注入可选的 `window.crewbaseDesktop`（`version`、`platform`、`quit()`、`openExternal(url)`、`setBadge(n)`）：外部链接用系统浏览器打开，Dock / 任务栏角标显示「需要你」的数量。普通浏览器中这些都不存在，界面照常工作。

**和 openbot / cindy 的区别**：我们**不用最左侧的竖向图标栏**。那是两家共同的标志性结构，照搬会让产品看起来像它们的换皮。会话列表只放「人和事」，其他东西各归其位：

- **统一设置**：所有设置收进一个「设置」页，入口在**左下角**：个人头像旁的齿轮。设置页左侧是「返回对话」、搜索框和分组导航，进入时会话列表让出位置。
- **模型选择在输入框里**：发消息前就能看到并切换「这条消息由哪个模型处理」，与运行权限下拉并排。菜单列出当前 Agent 的模型顺序、剩余额度和推理强度。
- **运行主机是输入框里单独的一个选择器**，和运行权限并排，见 5.6。
- **「需要你」**是对话标题栏右侧的琥珀色胶囊，有待处理事项时才出现，点开即可直接批准或去接管，不用离开当前对话。
- **⌘K 快速跳转**：频道、Agent、待处理事项、设置分区和命令（切换模型、切换权限、切换主机）都能搜到。

| 区域 | 内容 |
|---|---|
| 会话列表顶部 | 标题栏区域，只有会话列表开关（靠右）；桌面版左侧让出 macOS 红绿灯 |

| 会话列表 | 背景为画布色；搜索框与 ＋（新建 Agent / 频道 / 文件夹）同一行；「需要你」分组（处理后自动消失）；按项目文件夹分组的频道与 Agent。分组标题小号、灰色、加字距，带数量，可折叠。每行最多两行：头像（32）· 名字 · 右对齐时间；第二行是话题，没有话题时是最后一句。等你处理时第一行出现琥珀色「等你」小标签。选中行是白色内容面 + 细边框 + 极浅阴影，不用灰色填充。职责不在列表里显示（在对话标题栏和右侧面板） |
| 左下角 | 「你」头像 + 显示名 + 「本机 · 主机名」；齿轮直接进入设置（⌘,）。点头像打开个人菜单，见 5.1 |
| 对话区 | 内容列最宽 760、居中，两侧留白 24；用户气泡在内容列内靠右。Agent 消息：头像 28，名字与时间同一行；模型名只在与上一条 Agent 消息不同时显示（短名，如「Claude Opus 5.5」，推理强度非「中」时加小后缀），其余悬停时显示。系统说明（权限变更、模型切换、压缩、交接）居中、12px 灰字加小图标，连续几条合为一组。执行步骤是与正文对齐的轻量行，展开后左侧 2px 竖线。日期分隔是居中的灰色小字 |
| 输入框 | 与内容列同宽的浮起卡片（内容面、细边框、浅阴影、圆角 16），输入区最多长到约 8 行。下排左：添加附件、**运行主机**、运行权限（中性描边胶囊，只有宿主机授权用红色文字和图标）；右：**模型选择器**（厂商图标 + 模型短名）、语音、发送（有文字时为强调色实心，否则灰色不可用）；下方状态行：左侧工作目录（灰色等宽，中间省略），右侧订阅剩余额度与上下文环（占用为 0 时只显示环，点击展开上下文构成） |
| 右侧面板 | 任务（负责人、队列，可停止 / 改派 / 归档）、文件（工作区文件树与预览）、Agent 设置（模型顺序、推理强度、运行权限、上下文、记忆） |
| 设置 | 左侧：返回对话、搜索设置、三组分区。**你**：通用、个人资料与用量、通知、快捷键；**Agent**：模型与订阅、插件与技能、电脑操作、自动化、审批；**设备**：主机与设备 |
| 快速跳转 ⌘K | 频道、Agent、待处理事项、设置分区、命令；方向键选择，回车打开，Esc 关闭 |

**模型选择器为什么放在输入框里**：模型是「这条消息怎么处理」的属性，和运行权限一样，应该在发送前、在手边调整。右上角的位置离输入点远，而且在频道里容易被误解为「整个频道的模型」。输入框里的选择器只作用于当前 Agent（频道中为当前负责人），右侧面板的「Agent 设置」负责调整完整的模型顺序。

窄屏（< 820px）：会话列表变为浮层，由对话标题栏左侧的开关打开；右侧面板在 < 1100px 时变为浮层。

## 5. 新增交互

### 5.1 左下角：个人与设置

```text
┌──────────────────────────────┐
│ (夏) 林夏                  ⚙ │
│      本机 · MacBook-Pro       │
└──────────────────────────────┘
```

- **底栏**：「你」头像 + 显示名（`GET /api/settings` 的 `displayName`，未设置时为「你」）+ 副标题「本机 · 主机名」（`GET /api/system` 的 `hostname`）；开启免打扰时副标题改为「免打扰至 HH:mm」，头像右下角出现月亮。
- **齿轮**：直接进入设置（⌘,）。
- **个人菜单**（点头像，向上弹出，宽 280），自上而下：

```text
┌──────────────────────────────────┐
│ (夏) 林夏                         │  ← 点名字可直接改名
│      Crewbase 0.1.0 · 已运行 3 小时 │
│ ┌ 今天 › ───────────────────────┐ │
│ │ 73K      2         $4.20      │ │  ← 点击进入「个人资料与用量」
│ │ Tokens   自动切换   节省        │ │
│ └───────────────────────────────┘ │
│ ☾ 免打扰                     ( ) │  ← 1 小时 / 直到明天早上 8 点 / 关闭
│   需要你批准的事仍会通知             │
│ ⌨ 快捷键                          │
│ ⛑ 帮助与反馈                       │
│ ⚙ 设置                       ⌘,  │
│ ⏻ 退出 Crewbase                   │  ← 浏览器中为「断开连接」
│   Agent 会停止运行                 │
└──────────────────────────────────┘
```

| 项 | 说明 |
|---|---|
| 头部 | 头像 36 + 显示名（点击原地改名，`PATCH /api/settings {displayName}`）；副标题「Crewbase 版本 · 已运行 时长」，来自 `GET /api/system`（`version`、`startedAt`、`hostname`、`os`、`arch`、`dataDir`） |
| 今天 | 三个小统计：今天的 tokens、自动切换模型次数、订阅复用节省（`GET /api/usage`）；点击进入设置 › 个人资料与用量 |
| 免打扰 | 开关 + 时长子菜单（1 小时 / 直到明天早上 8 点 / 关闭），写入 `PATCH /api/settings {dndUntil}`（RFC 3339，空字符串为关闭）。说明「需要你批准的事仍会通知」 |
| 快捷键 | 打开设置 › 快捷键 |
| 帮助与反馈 | 打开项目 Issues（桌面版用系统浏览器） |
| 设置 | 打开设置（⌘,） |
| 退出 | 桌面版：「退出 Crewbase」，并注明「Agent 会停止运行」；浏览器：「断开连接」（清除这台设备上保存的令牌） |

外观（主题）不在个人菜单里，只在设置 › 通用；「连接手机」在功能可用前不出现。

### 5.2 新建 Agent

入口：会话列表右上角 ＋ → 新建 Agent；或 ⌘N；或 ⌘K 输入「新建」。

1. 对话标题栏显示「新建 Agent」和实时的头像预览，对话区变成表单，会话列表保留。
2. 顶部是大头像预览，下面选颜色（18 种）和形状（7 种），名字实时显示在头像下方。
3. **名称**（必填）、**这个 Agent 负责什么**（写入 `INSTRUCTIONS.md`，之后可改）。
4. **模型**：选择主模型和推理强度；下方提示「额度用完时自动改用 Codex，工作区和上下文都会保留」。这是我们和竞品的差异点，在创建时就让用户知道。
5. **运行权限**：只读调研 / 容器沙箱（默认）。宿主机授权不能在创建时开启。
6. **放在**：选择项目文件夹。
7. 下方「从模板开始」：代码审查员、竞品观察员、周报助手，点一下填好全部字段，仍可修改。
8. 创建后打开与它的对话，第一条消息由它自我介绍并说明工作目录。名称为空时提示「先给它起个名字」并聚焦输入框。

新建频道：频道名、成员（多选，第一个选中的是负责人）、放在哪个文件夹。新建文件夹：直接出现在列表中，空文件夹显示提示。

### 5.3 上下文用量

点输入框下方的「上下文 62%」打开浮层：

- 分段条：系统提示词、记忆文件、工具定义、技能与子 Agent、工具调用与结果、消息、剩余空间；80% 处有一条阈值线。
- 明细：每类的 token 数；总量与当前模型的窗口（如 124K / 200K · Codex）。
- 说明：「达到 80% 时自动压缩：保留指令、记忆和最近的步骤，较早的对话会被摘要，原文仍可用 history_search 找回。」
- 操作：**立即压缩**；**新对话**（同一个 Agent，新的上下文，工作区、记忆和队列不变）。

### 5.4 个人资料与用量

设置 › 个人资料与用量（也可从个人菜单的「今天」进入）：

- 统计卡片：Tokens、峰值日、消息数、**自动切换模型次数（其中需要人工介入的次数）**、**订阅复用节省（对比按 API 计费）**。后两项体现我们的核心价值。
- 这台电脑上的活动热力图（过去 53 周，五档深浅）。
- 模型来源占比：分段条 + 列表（带 LobeHub 图标），最忙的一天、估算成本。
- 最活跃的成员：Agent 头像、角色、当前模型、token 数，点击进入对话。
- 页面注明「只统计这台电脑上的数据，不会上传」；分享时生成不含对话内容的图片。

### 5.5 模型与订阅

设置 › 模型与订阅。参考 LobeChat 的提供方设置，但把「复用订阅」放在第一位。顶部分段：**提供方** / **路由与切换**；右上角「添加提供方」。

**提供方**（左列表 + 右详情）

| 分组 | 包含 | 详情页内容 |
|---|---|---|
| 订阅（复用 CLI 登录） | Claude Code、Codex、Gemini CLI、Grok CLI | 账号、CLI 版本与路径、协议（ACP）；额度条（5 小时窗口 / 本周，用完显示红色和重置时间）；重新检测、在终端中打开、退出登录；可用模型（由订阅决定，开关控制对 Agent 是否可见） |
| API | DeepSeek、Anthropic、OpenAI，以及用户添加的 | API Key（保存到系统钥匙串，配置只存 `keychain:crewbase/<id>` 引用）；Base URL；测试连接（显示延迟）；本月花费；模型列表（获取模型列表、搜索、能力标签、上下文、价格、启用开关）；移除提供方 |
| 本地模型 | Ollama、LM Studio | 服务地址；自动发现的模型（含大小）；重新扫描；拉取新模型；服务未运行时给出原因 |

- 列表项右侧圆点：绿 = 已连接，红 = 额度用完，无点 = 未配置 / 已停用。
- 详情顶部显示「正在使用：Kai、Iris」，点击跳到对话；订阅额度用完时补一句「已自动切到各自的备用模型」。
- **未登录的 CLI**（如 Grok）：显示检测到的版本和路径、复制 `grok login` 命令、「我已登录，重新检测」。Crewbase 不保存账号密码，登录由 CLI 自己完成。
- 能力标签：工具、视觉、推理、长上下文、编码、嵌入，颜色区分。
- 获取模型后，**新出现的模型默认不启用**，避免 Agent 突然用上未经确认的模型。

**添加提供方**（弹窗，两步）

1. 选择提供方：搜索 + 卡片网格（LobeHub 图标）：OpenAI、Anthropic、OpenRouter、阿里云百炼、Moonshot（Kimi）、智谱 GLM、豆包、MiniMax、SiliconFlow、Azure OpenAI、Groq、Mistral、自定义（OpenAI 兼容）。已添加的置灰。底部说明：订阅类不在这里添加，安装并登录 CLI 后自动检测。
2. 填写 API Key（必填）与 Base URL（已预填）→「测试并获取模型」→ 显示连接结果和模型清单（默认勾选前两个，可全选）→「添加」。添加后自动选中该提供方。

**路由与切换**

- 新 Agent 的默认模型顺序（可上下调整），每个 Agent 可在自己的设置里覆盖。
- 切换规则：额度用完或限流时自动切换（开关）；额度恢复后切回首选模型（仅新任务 / 不切回）；额度剩余 10% 时提醒（开关）。
- 按任务分流：网页摘要与日志清洗 → 本地模型；编码 → Claude Code；超长文档 → Gemini CLI；嵌入 → 本地；并显示节省效果。

### 5.6 运行主机

输入框里有两个并排的选择器：**在哪台机器上运行**（运行主机）和**能做什么**（运行权限）。两者独立：主机决定命令和文件操作落在哪台机器，权限决定在那台机器上被允许做什么。

```text
[+] [🖥 本机 ▾] [✋ 容器沙箱 ▾]                [■ Codex · 中 ▾] [🎤] [↑]
```

主机菜单（作用于当前 Agent；频道中为当前负责人）：

| 项 | 显示 |
|---|---|
| 本机 · MacBook Pro | 在线 · macOS · Docker 可用 |
| ecs-hangzhou | 在线 · 阿里云 · Ubuntu 24.04 · 延迟 38ms |
| 家里的 Mac mini | 离线 · 2 小时前在线（置灰，不可选） |
| 添加主机 | 跳到设置 › 主机与设备，运行 `install-server.sh` 后扫码配对 |

切换主机时，输入框上方展开蓝色确认条，说明：之后的命令和文件操作都在新主机上执行；工作区是 Git 仓库，会在新主机上同步到同一分支，未提交的文件一起带过去；当前步骤完成后再切换。确认后对话中插入一行「林夏 把 Kai 换到 ecs-hangzhou 运行 · 工作区已同步到同一分支」。

主机会影响权限菜单：

- 菜单标题显示当前主机，如「Kai 的运行权限 · ecs-hangzhou」。
- 「宿主机授权」的说明随主机变化（「直接在 ecs-hangzhou 上执行」）。
- 主机可以有自己的策略。团队服务器的管理员可以禁止宿主机授权，此时该项置灰并说明原因；把一个处于宿主机授权的 Agent 换到这类主机时，权限自动改为容器沙箱，确认条中会提前写明。

输入框下方的状态行只显示工作目录（如 `~/code/site`）。

### 5.7 设置页各分区

| 分组 | 分区 | 内容 |
|---|---|---|
| 你 | 通用 | **外观**：主题（跟随系统 / 浅色 / 深色）、语言、界面大小（90%–125%）、界面字体、代码字体、图标颜色（10 种）、我的消息颜色。**启动与后台**：开机时启动、关闭窗口后继续运行（Agent、定时任务、审批都不中断）、在菜单栏显示。**新 Agent 的默认值**：运行权限（宿主机授权不能作为默认）、模型顺序（链接到路由与切换） |
| 你 | 个人资料与用量 | 见 5.4 |

| 你 | 快捷键 | 按组列出（通用：⌘K、⌘N、⌘,、Esc；对话：⌘[ / ⌘] 上一个 / 下一个对话、⌘Enter 发送、@ 提到成员；审批、窗口），可搜索；点按键组合进入录制，按下新组合即保存，Esc 取消；与已有快捷键冲突时提示并拒绝；改过的项显示默认值和「恢复默认」，页头「恢复全部默认」。Windows / Linux 上 ⌘ 对应 Ctrl |
| Agent | 模型与订阅 | 见 5.5 |
| Agent | 插件与技能 | 按主机安装、分类、授权 |

**没有「权限规则」设置页。** Allow / Ask / Block 的默认值覆盖大多数情况（读文件、执行命令、安装依赖直接执行；推送代码、删除文件、对外发消息先问你；外部支付一律拦截）。需要调整时，在审批卡上点「以后都允许」：本次批准，并记住该 Agent 的这类操作。记住的选择列在「审批」分区，随时可以撤销。这样规则在做决定的时候调整，而不是让用户事先面对一张抽象的表。

## 6. 核心流程

### 4.1 任务交接

1. 人在频道中 @ 某个 Agent 指派任务，该 Agent 成为负责人。
2. 负责人完成阶段工作，发起交接：目标 Agent、交接说明、产物文件。
3. 对话中插入「Nova 把任务交给了 Kai」；接收方成为新负责人。文件以引用移交，不复制。
4. 人随时可以在右侧面板停止、改派、归档。改派时显示各 Agent 队列长度。

### 4.2 审批挂起与恢复

1. Agent 的工具调用命中 Ask 规则（如 `git push`、对外发帖），工具执行流水线挂起该调用，执行流停在断点。
2. 同时出现在三处：对话内审批卡、会话列表「需要你」、对话标题栏「需要你」胶囊（可直接批准）；桌面版的 Dock / 任务栏角标同步计数；并推送到移动端或 IM。
3. 审批卡展示：谁、要做什么（完整命令或内容预览）、命中的规则、影响范围。
4. 批准 → 从断点继续；拒绝 → Agent 收到拒绝原因并重新规划；无人可答或超时 → 视为拒绝。

### 4.3 限额无损切换

1. 主模型返回限流或额度耗尽，调度器按 Agent 的模型顺序选择下一个可用模型。
2. 新模型从同一份会话日志重建请求，Agent 身份、工作区、队列不变。
3. 对话插入一行：「Kai 的 Claude Code 已达本周上限 · Kai 现在使用 Codex」，不发通知。
4. 额度重置后，下一个新任务回到首选模型；进行中的任务不打断。

### 4.4 浏览器接管

1. Agent 遇到登录、2FA 或验证码，状态变为「等待你」并暂停。
2. 人点击「接管浏览器」，画面加蓝色描边；Agent 不读取画面与输入。
3. 完成后点击「交还控制权」，Agent 从已登录状态继续；凭证不进入提示词与日志。

### 4.5 切换运行权限

1. 在输入框的权限下拉或右侧面板选择「只读调研 / 容器沙箱 / 宿主机授权」。
2. 选「宿主机授权」时，输入框上方先展开红色确认条，说明影响并默认 24 小时后恢复沙箱。
3. 规则引擎的 Ask / Block 在任何模式下都继续生效。

### 4.6 安装插件或技能

1. 在「插件与技能」页选择目标主机（本机或某台远程主机）。
2. 安装前展示插件声明的权限（文件、网络、进程、凭证）和运行方式（进程内 / 独立进程 / 容器）。
3. 第三方插件需要用户批准权限后才会启用；停用后其注册的工具、界面、监听器全部撤销。
