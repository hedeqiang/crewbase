# ADR-0002：插件分四档运行

- 状态：提议
- 日期：2026-11-14

## 背景

Harness 基于 Node.js，插件在进程内动态加载、热替换（`dsh-hmr` 先卸载旧实例、回卷其副作用，再加载新代码）。Go 做不到同样的事：

- 标准库 `plugin` 包不支持 Windows，加载后不能卸载，且要求插件与主程序用完全相同的编译器版本和依赖版本构建。
- 进程内运行第三方代码意味着它与守护进程共享全部权限。Harness 自己的文档也指出，其桥接的 Claude Code 模组拥有进程全部权限、不受沙箱约束。

我们既需要官方核心插件的性能和类型安全，又需要第三方插件的隔离、热重载和多语言支持。

## 决策

插件按运行形态分四档，四档共用同一套概念（服务、事件、副作用、作用域、权限声明）。

| 档位 | 形态 | 谁用 | 隔离 | 热重载 |
|---|---|---|---|---|
| 内置 | 编译进 `crewd`，进程内 | 官方核心插件 | 无（受信任） | 可启停；替换代码需重启 |
| 进程外 | 子进程，stdio 上的 JSON-RPC 2.0 | 第三方工具、适配器、网关、沙箱后端 | 进程边界 + 可选容器 + 权限清单 | 重启子进程 |
| WASM | wazero 运行时，宿主进程内 | 高频纯函数钩子：规则判定、脱敏、流式块转换 | 内存隔离、默认无系统调用 | 支持 |
| 内容型 | MCP 服务器、技能文件夹、角色模板 | 外部服务、任务方法 | 由 `shell` / `sandbox` 托管 | 支持 |

### 进程外桥接约定

1. 子进程启动后发送清单（名称、版本、需要的服务、提供的服务、监听的事件、权限）。
2. 宿主中的代理插件只暴露清单中声明且用户批准的服务；替子进程向 `ctx` 注册工具、提供方、监听器，并记录撤销函数。
3. 子进程退出或崩溃 → 代理插件卸载 → 所有注册撤销 → 依赖它的插件进入 PENDING。
4. 外部插件监听 Waterfall 事件时有超时（默认 2 秒），超时视为「调用 `next()` 且不做改动」并记录警告；监听 Serial 事件超时则该监听方报错，不阻塞其他监听方。
5. 远程描述符由代码生成，参数必须与描述符完全一致；热卸载后不降级为更弱的校验。
6. SDK：Go、TypeScript、Python 三种语言，提供与内置插件相同的类型定义。

## 后果

- **正面**：第三方插件可用任何语言编写，崩溃不影响宿主，权限可审计；与 MCP / LSP / ACP 一致的协议让开发者容易上手。
- **负面**：进程外调用有序列化与 IPC 开销，不适合每个流式块都触发的高频钩子（这类钩子用 WASM 档）；需要维护三种语言的 SDK。
- **待验证**：Phase 0 测量 stdio JSON-RPC 往返延迟；目标是本机 p99 < 5 ms。
