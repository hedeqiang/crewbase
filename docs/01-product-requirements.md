## 设计要点

1. **插件优先的内核**。借鉴 DeepSeek Harness「一切皆插件」的做法：除了一个很小的插件宿主，模型适配器、工具、沙箱、审批策略、记忆、频道协作乃至 Agent 循环本身都是可替换的插件。详见 [插件系统](05-plugin-system.md)。
2. **能力 = 定义 + 提供方 + 消费方**。沙箱、Shell、文件系统、浏览器、子 Agent 等每一项能力都拆成三种角色。换一个提供方（例如把本地 Shell 换成远程容器），所有使用它的工具一起迁移，不需要分叉代码。
3. **模型可见即已记录**。每次模型请求都必须能从会话日志重建。这是无损模型切换、崩溃恢复、审计和 fork 的共同基础。
4. **如实描述安全边界**。沙箱和审批只能降低风险，不能保证隔离。产品文案和文档不承诺「绝对安全」。
5. **交互原型**见 [交互设计](03-ux-design.md) 与根目录的 `crewbase-prototype.html`。

## 1. 背景与痛点

以 Grok Bot、OpenAI Dots、Claude Duet、Manus 2.0 为代表的「全天候 AI 同事」产品正在改变人机协作：Agent 不再只是问答工具，而是拥有独立计算环境、浏览器、文件系统和长期记忆的执行体。现有产品有三类问题。

**订阅成本高，且按用量叠加。** Grok Bot 个人订阅分 Premium（$30/月）、Super（$100/月）、Ultra（$200/月），超出每周额度后还要按 token 计费。OpenAI Dots、Claude Duet 同样绑定各自的高阶订阅。

**模型锁定，无法自由路由。** 闭源产品绑定自家模型，用户不能按任务选模型（编码用 Claude / Codex、长文推理用 Gemini、摘要用本地 Ollama），单个模型限流或故障时也无法切换。

**开源方案在「商用自由」与「安全 / 协同」之间有断层。**

- OpenBot 的 Local-First 工作区和多 CLI 订阅复用做得很好，但据调研，其许可证在 v0.1.11 后改为 PolyForm Noncommercial 1.0.0，企业不能免费商用；默认以全权限、无审批的方式在本机运行。*（许可证变更引自 Benchclaw 的分析，发布前需对照 OpenBot 仓库再次核实。）*
- OpenClaw 社区大、AgentSkills 多，但代码量约 43 万行，所有 Skill 共享单进程权限边界。
- nanobot、PicoClaw 极轻量（Go，内存 <10MB），但缺少多 Agent 分工、共享工作区和团队协同。
- DeepSeek Harness（MIT）插件架构最彻底，但面向开发者，目前是单人、单会话视角，没有多 Agent 频道协作、订阅复用或团队部署形态，并且自述「开发者预览，未经安全审计」。

## 2. 产品定位

**一句话**：复用你已有的模型订阅和本地算力，用一套可审计、可自托管、可商用的开源软件，组建一支 24/7 工作的 AI 团队。

**三个关键词**

- **Local-First**：工作区、会话、文件、浏览器数据默认保存在运行它的机器上。
- **Model-Agnostic**：Agent 是实体，模型是可替换零件。
- **Plugin-First**：产品的每一部分都可以通过插件替换或扩展，没有需要打补丁的特权内核。

## 3. 目标用户

| 用户 | 典型场景 | 最看重 |
|---|---|---|
| 独立开发者、技术极客 | 同时调度 Claude Code、Codex、Gemini、本地 Ollama，完成「调研 → 编码 → 测试 → 审查」 | 不重复付费、不被单一厂商锁定、能写插件 |
| 一人公司、自动化运营团队 | 24/7 竞品跟踪、数据汇总、内容起草、异常巡检 | 对外发布必须人工批准、无异常不打扰 |
| 中小研发与业务团队 | 在内网或阿里云 / AWS / VPS 私有部署，多人与多个 Agent 共用项目目录 | 可商用协议、权限治理、审计日志 |
| 插件与集成开发者（新增） | 为团队或社区开发工具、模型适配器、沙箱后端、IM 网关 | 稳定的扩展点、清晰的文档、热重载 |

## 4. 功能需求

优先级：**P0** 为 MVP 必须，**P1** 为第二阶段，**P2** 为第三阶段。

### 4.1 多模型路由与订阅复用

| 编号 | 需求 | 优先级 |
|---|---|---|
| M-1 | 通过 ACP（Agent Client Protocol）和子进程管理，桥接用户已登录的 Claude Code、Codex、Gemini CLI、Grok CLI、Cursor CLI、OpenCode，直接复用其订阅额度 | P0 |
| M-2 | 原生支持 OpenAI-compatible、Anthropic、Gemini、xAI、DeepSeek、Moonshot、Qwen 等 API | P0 |
| M-3 | 自动发现本地 Ollama / LM Studio / vLLM 服务 | P0 |
| M-4 | 每个 Agent 配置有序的模型列表和推理强度；主模型限流、额度耗尽或故障时，自动切到下一个，保留工作区、上下文和待办队列 | P0 |
| M-5 | 按任务类型分流（如网页摘要、日志清洗走本地模型），并在界面上显示节省的 token | P1 |
| M-6 | 每个模型提供方都是一个插件，第三方可以发布新的适配器 | P0（机制）/ P1（市场） |

验收要点：触发限额后 5 秒内完成切换；切换前后的会话可从日志完整重建；频道内出现一条切换说明，但不发通知。

### 4.2 持久化 Agent 与多角色协同

| 编号 | 需求 | 优先级 |
|---|---|---|
| A-1 | 每个 Agent 有独立工作目录 `workspaces/<agent-id>/`、角色指令 `INSTRUCTIONS.md`、长期记忆（`MEMORY.md` + SQLite 全文索引）、独立浏览器 Profile、可恢复的 FIFO 队列（暂停、恢复、插队、取消） | P0 |
| A-2 | 每个 Agent 可以有自己的工具集、提示词和模型。实现上用「作用域注册」：同名的私有工具覆盖全局工具，限制规则只对该 Agent 生效 | P0 |
| A-3 | 共享频道：多个 Agent 与人类成员共享上下文和文件引用 | P1 |
| A-4 | 单一负责人（One Task Owner）：同一时刻只有一个 Agent 推进任务，完成后显式交接给下一个 Agent，并移交产物文件 | P1 |
| A-5 | 人可以随时停止、恢复、改派、归档任务 | P1 |
| A-6 | 子 Agent 委派：负责人可以临时启动子 Agent 并行处理，子 Agent 的父子关系以数据记录，不自动继承父 Agent 的私有工具 | P1 |
| A-7 | 团队任务板：一棵子 Agent 树共享一个任务 DAG（有向无环图），每个任务有唯一负责人 | P2 |

### 4.3 自动化：Routines 与 Workflows

| 编号 | 需求 | 优先级 |
|---|---|---|
| R-1 | Routines：按 Cron 或 Webhook 触发单个 Agent 的例行巡检；无异常时静默 | P1 |
| R-2 | 晨报（Morning Brief）：每天汇总需要人处理的事项，正常项折叠 | P1 |
| R-3 | Workflows：把「触发器 → 多 Agent 串并行步骤 → 审批卡点 → 发布」编排成可复用流水线 | P1 |
| R-4 | 持久目标（Goal）：为一个会话设置完成目标，系统按轮次自动续跑，直到完成、阻塞或达到轮次上限；恢复或重启后需人重新授权才能继续自动工作 | P2 |
| R-5 | 工作流、巡检、目标都是插件提供的「策略」，而不是写死在 Agent 循环里 | P1 |

### 4.4 安全与治理

详见 [安全模型](06-security-model.md)。

| 编号 | 需求 | 优先级 |
|---|---|---|
| S-1 | 三档运行模式，可按 Agent 或单次任务指定：A 只读调研、B 容器沙箱（默认）、C 宿主机授权 | P0（B/C）/ P1（A） |
| S-2 | 规则引擎：按动作类别（对外发布、代码推送、文件删除、命令执行、外部支付等）配置 Allow / Ask / Block | P0 |
| S-3 | Ask 时挂起执行流，人批准后从断点继续；没有可用的审批人时一律视为拒绝 | P0 |
| S-4 | 凭证保险箱：配置里只存凭证引用，值保存在系统钥匙串；凭证不进入模型提示词，日志与记忆自动脱敏 | P0 |
| S-5 | 浏览器接管：人临时接管 Agent 的浏览器完成登录、2FA、验证码，期间 Agent 不读取画面与输入 | P0 |
| S-6 | 第三方插件默认在独立进程或容器中运行，需要声明权限并经用户批准才能启用 | P1 |
| S-7 | 审计日志：每次规则判定、审批、插件启停都写入不可篡改的日志 | P2 |

### 4.5 上下文与生态

| 编号 | 需求 | 优先级 |
|---|---|---|
| C-1 | 追踪各会话的上下文占用，默认 80% 触发压缩；保留指令、近期对话和关键步骤快照 | P0 |
| C-2 | 提供 `history_search` / `history_read` 工具，按需召回早期细节 | P1 |
| C-3 | 兼容 MCP（Model Context Protocol）连接器：Linear、Notion、GitHub、Obsidian、Postiz、飞书等 | P0 |
| C-4 | 技能（Skills）按需加载：Agent 只看到技能目录，需要时才加载全文，不占常驻上下文 | P1 |
| C-5 | 插件与技能市场：按目标主机安装、启用、停用；一键导入 Grok Bot / Hermes 角色模板（只迁移指令与流程，不迁移对话和记忆） | P1 |

### 4.6 多端与部署

| 编号 | 需求 | 优先级 |
|---|---|---|
| D-1 | 桌面端（macOS / Windows / Linux）单一可执行文件，系统托盘常驻、自动更新 | P0 |
| D-2 | 远程主机：阿里云 ECS、AWS EC2 / ECS、通用 VPS、家用 Mac mini；不暴露入站端口，通过 WebSocket Relay / Tailscale / WireGuard 主动出站配对 | P2 |
| D-3 | 移动端伴侣：接收通知、处理审批、查看进展，不运行 Agent | P2 |
| D-4 | IM 网关：Slack、Telegram、Discord、飞书 / Lark，可在 IM 中接收进展和完成审批 | P2 |
| D-5 | 运行形态由「Profile」决定：同一套插件可组装为桌面版、无头服务器版、SDK 版、ACP 服务器版 | P1 |

## 5. 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 守护进程空闲内存 < 80MB（不含模型与浏览器）；冷启动 < 1.5 秒；单机同时运行 ≥ 8 个 Agent |
| 可靠性 | 进程崩溃后，会话可从日志恢复到最后一个完整步骤；退出时清理所有 MCP / CLI 子进程树 |
| 可扩展性 | 新增模型提供方、工具、沙箱后端、IM 网关都不需要修改内核代码 |
| 可观测性 | 每次模型请求可从日志重建；支持导出 OpenTelemetry |
| 隐私 | 默认不上报遥测；如提供，必须显式开启并说明内容 |
| 国际化 | 中文、英文同步发布；文档双语配对维护 |

## 6. 成功指标（MVP 后 3 个月）

- 周活跃安装 ≥ 3,000；其中 ≥ 40% 同时连接了 2 个以上模型来源。
- 因限额触发的自动切换中，≥ 95% 无需人工介入即可继续任务。
- 默认配置下，0 起已知的「未经审批执行高危操作」事件。
- 社区发布的第三方插件 ≥ 30 个。

## 7. 开源协议与商业化

- 核心引擎、客户端、官方插件与技能模板统一采用 **MIT**（2026-11-15 由 Apache-2.0 改为 MIT，更简单、更宽松）。
- 借鉴 DeepSeek Harness（MIT）的设计思想不产生许可证义务；如直接复用其代码，需要保留其版权与许可声明，保留声明即可合法包含。
- **社区版**免费且功能完整，不做人为阉割。
- **商业版**：托管云主机（24/7）、SSO、细粒度 RBAC、DLP 策略、定制集成与支持。
