# 竞品与参考分析

本文对比主要竞品与参考产品，说明我们从每一家吸收什么、在哪里超越。DeepSeek Harness 的技术细节较多，单独整理在 [参考笔记](references/deepseek-harness.md)。

## 1. 能力对标

| 产品 | 核心优势 | 核心短板 | 我们的吸收与超越 |
|---|---|---|---|
| **OpenBot** | 多 Agent 频道协同与显式交接；通过 CLI / ACP 复用 ChatGPT、Claude、Gemini、Grok 订阅；达到上限时切换备用模型并保留工作区 | 据调研为 PolyForm Noncommercial 协议（待核实）；默认全权限、无审批 | Apache-2.0；保留订阅复用与无损切换；默认容器沙箱 + 人工审批 |
| **DeepSeek Harness** | 「一切皆插件」：Agent 循环、工具注册表、会话日志、模型适配器都是可替换插件；能力拆成定义 / 提供方 / 消费方；工具执行流水线有完整的拦截点；会话日志是唯一真源 | 面向开发者，单会话视角；没有多 Agent 频道、订阅复用和团队部署；自述未经安全审计 | 用 Go 重写同样的插件内核思想，作为我们的技术底座；在其上做多 Agent 协作、订阅路由与团队治理（见 [插件系统](05-plugin-system.md)） |
| **Grok Bot** | 接入 Slack / Teams / Meet；可示范教学（Teach a task）；自动沉淀团队偏好 | $30–$200/月 + 超额 token 费；只能用 Grok | 可复用的定时 / 触发式工作流；本地可编辑的长期记忆；模型自由路由 |
| **OpenAI Dots** | 单 Agent 后台并行推进多个项目；只读后台调研；Custom Rules（允许 / 需审批 / 禁止）与自动审查 | 闭源云端托管；绑定 OpenAI 高阶订阅 | 吸收分级规则引擎和只读调研模式；数据默认本地存储 |
| **Claude Duet** | 每日主动汇总（Morning Brief），平时静默；关键动作挂起等人确认 | 仅美国区高阶订阅候补；缺少本地文件深度控制 | 内置晨报与事件触发；端到端的挂起与审批恢复 |
| **Manus 2.0** | Cascade Harness 按需加载能力，实测减少 23.2% token、32% 成本；执行中可人工接管浏览器和沙箱 | 闭源计费，长周期任务成本不可控 | 技能与 MCP 按需挂载；持久化隔离浏览器的实时接管 |
| **OpenClaw** | 打通 WhatsApp、Telegram、Discord、Slack；人类可读的 Markdown 记忆 | 约 43 万行代码；单进程隔离薄弱，第三方 Skill 有越权风险 | 轻量 Go 内核 + 插件化 IM 网关；第三方插件强制进程外或容器隔离 |
| **Cindy** | 多设备连接同一任务；会话按项目分组；输入框内切换权限；右侧文件面板；按目标电脑管理技能；多 Harness（Claude Code / Codex / Pi）切换 | 闭源（标称开源但以品牌叙事为主）；团队治理能力不明确 | 借鉴其 App 信息架构：项目分组、右侧面板、输入框状态行、按主机管理插件 |

## 2. 为什么选 DeepSeek Harness 作为技术参考

在所有开源方案中，Harness 是唯一把「可替换」贯彻到内核本身的项目，并且文档详细、协议宽松（MIT）。它解决的问题，恰好是「把功能写成固定模块」的设计最容易出问题的地方：

| 固定模块的问题 | Harness 的做法 | 对我们的意义 |
|---|---|---|
| 沙箱、审批、路由写成固定模块，扩展要改内核 | 没有特权内核，所有部分都是插件，注册即副作用，卸载即撤销 | 社区可以贡献沙箱后端、IM 网关、模型适配器而不碰内核 |
| 「三档沙箱」只是三个开关 | 沙箱是一个能力：定义 `ctx.sandbox`，多个后端作为提供方，消费方在启动进程前包装命令 | 本地 Docker、远程 SSH、云端容器只是不同提供方 |
| 审批逻辑与工具执行耦合 | 工具执行流水线有 `pre-execute → 守卫 → execute → post-execute → result` 拦截点，审批只是其中一个监听器 | 规则引擎、Hook、审计、超时、重试都能独立开发和组合 |
| 模型切换需要「迁移上下文」 | 会话日志是唯一真源，模型历史从日志投影得到 | 切换模型只是换一个适配器，从同一份日志重建请求 |
| 每个 Agent 的个性化靠配置字段 | 作用域注册：全局 + 每个 Agent 两层，同名覆盖，限制取交集 | 每个 Agent 的工具、提示词、限制都能独立插拔 |

我们和 Harness 的定位不同：Harness 是开发者的 Agent 运行时，我们是面向个人和团队的多 Agent 工作台。我们借鉴的是内核设计，产品层（频道、交接、订阅路由、团队、部署）需要自己构建。

## 3. 差异化总结

1. **唯一同时满足「可商用 + 默认安全 + 多 Agent 协作 + 复用订阅」的开源方案**。
2. **插件优先的 Go 内核**：比 OpenClaw 轻量，比 OpenBot 可扩展，比 Harness 更贴近团队协作场景。
3. **团队形态**：私有部署、零入站端口、移动端审批、IM 网关。
